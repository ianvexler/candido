# CV Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user upload their existing CV (PDF or Word) and turn it into library sections and profile details, after reviewing what was found.

**Architecture:** The upload creates a `cv_imports` row and a background job. The job sends the file to Claude, which returns JSON in a fixed shape (structured output). Plain Ruby code validates and normalises that JSON into a draft: section attributes with escaped HTML content, plus header fields. The client polls the import, shows the draft for review, and applies only what the user ticks. Applying creates section templates and fills only the empty profile fields. Only `CvImports::Extractor` knows about Claude, so the model or provider can be swapped there.

**Tech Stack:** Rails 8 (ActiveJob, Shrine-free in-row storage), `anthropic` gem 2.12 (beta messages with structured output and server-side fallbacks), `rubyzip` + Nokogiri for `.docx` text, RSpec. Next.js client, using the existing dialog and checkbox components.

**Spec:** No separate spec file. These are the decisions agreed in the session that produced this plan:
1. Use one model, Claude Opus 5.5 at low effort, behind a single service, so it can be swapped later.
2. Send PDFs directly to the model (it reads the layout). Convert `.docx` to text in Rails.
3. Use structured output in a fixed shape that matches the header fields and section fields.
4. Build section HTML in code from escaped text; never trust model HTML.
5. Always show a review step. Never overwrite what the user already wrote.
6. Run in the background; the client shows progress.
7. Tell the user the CV is sent to Anthropic. Don't keep the file after reading it.

## Global Constraints

- Branch: `feature/cv-import`, from `main`.
- Model: `ENV.fetch("CV_IMPORT_MODEL", "claude-opus-5-5")`.
- Request: `client.beta.messages.create` with `betas: ["server-side-fallback-2026-07-01"]`, `fallbacks: :default`, `max_tokens: 16_000`, and `output_config: { effort: :low, format_: { type: :json_schema, schema: SCHEMA } }`. This exact shape was verified against gem 2.12.0 by capturing the request body.
- PDF block: `{ type: "document", source: { type: "base64", media_type: "application/pdf", data: <base64> } }`. DOCX is sent as a text block holding the extracted text.
- Accepted uploads: `application/pdf` and `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, detected with Marcel. Maximum 5 MB.
- At most 10 imports per user per rolling 24 hours (cost protection). The 11th returns 429.
- With no `ANTHROPIC_API_KEY`, `POST /cv_imports` returns 503 with "CV import isn't available right now."
- Normaliser limits: 40 sections, 60 blocks per section, text fields 200 chars, block text 2000 chars, 10 links.
- Import statuses: `pending`, `processing`, `succeeded`, `failed`.
- The source file (base64) is cleared once the job finishes, whatever the outcome.
- User-facing copy is sentence case. The button reads **Import from CV**.

## Review Focus

1. **A model reply that doesn't match the schema** (a refusal, cut off at `max_tokens`, or invalid JSON) must end as a `failed` import with a clear message, never a stuck "processing" one. Tests in Task 2 and Task 3.
2. **Hostile or odd content in the CV** (`<script>`, HTML-looking text, `javascript:` links) must end up as plain text in sections and be dropped from links. Tests in Task 1.
3. **Applying twice, or applying another user's import**, must not create duplicate sections and must not leak data. Tests in Task 3.
4. **Existing profile values** must never be overwritten by imported ones. Only blank fields are filled, and links are added without duplicates. Tests in Task 3.
5. **A scanned or empty CV**, where the model finds nothing, must say so ("We couldn't find any sections in this file") instead of showing an empty review. Tests in Task 1 (empty draft) and Task 4 (message).

### Task 1: Draft normaliser and import record

**Files:**
- Create: the migration, `backend/app/models/cv_import.rb`, `backend/app/services/cv_imports/draft.rb`, `backend/spec/factories/cv_imports.rb`
- Modify: `backend/app/models/user.rb` (`has_many :cv_imports, dependent: :destroy`)
- Test: `backend/spec/services/cv_imports/draft_spec.rb`

**Interfaces:**
- Produces: `CvImports::Draft.from_model_output(hash) -> Hash` with string keys:
  - `"header"`: the same keys as `ResumeHeader.normalize_profile`.
  - `"sections"`: an array of hashes with the `SectionTemplate` attribute names (`title`, `section_type`, `description`, `content`, `role`, `organization`, `location`, `start_date`, `end_date`, `current`).
  - Model output keys (from Task 2's schema): `header{name, headline, email, phone, location, links[{label,url}]}`, `sections[{section_type, title, role, organization, location, start_month, end_month, current, summary, blocks[{kind, text}]}]`, where `kind` is one of `bullet` / `paragraph` / `heading`.
- Produces: `CvImport::STATUSES`, `CvImport::DAILY_LIMIT = 10`, `CvImport.find_owned!(user, id)` (404 or 403 as `ApiError`), `CvImport.limit_reached?(user)`.

- [ ] **Step 1: Write failing specs** for `Draft.from_model_output`:
  - **Blocks to HTML:**
    - consecutive bullets become one `<ul><li><p>…</p></li></ul>`;
    - a paragraph becomes `<p>…</p>`;
    - a heading becomes `<h3>…</h3>`;
    - order is kept.
  - **Escaping:** `<script>alert(1)</script>` comes out escaped. The content contains no `<script`.
  - **Dates:**
    - `"2022-03"` becomes `Date 2022-03-01`;
    - `"March 2022"` and `""` become `nil`;
    - an end before the start drops the end;
    - `current: true` drops the end.
  - **Fallbacks:** a blank title falls back to the section type, then `"Untitled"`. A blank type becomes `"Section"`.
  - **Header:**
    - text is trimmed;
    - `javascript:` links are dropped;
    - a bare domain gets `https://`;
    - at most 10 links are kept.
  - **Limits:** 45 sections are capped at 40. A 3000-char block is cut to 2000.
  - **Empty input:** `{"sections" => []}` gives an empty sections array, and missing keys don't raise.
- [ ] **Step 2: Run** `./run rspec spec/services/cv_imports/draft_spec.rb`. Expected: FAIL (uninitialized constant).
- [ ] **Step 3: Implement.** Generate the migration and model, then `Draft`:
  - escape text with `ERB::Util.html_escape`;
  - reuse `ResumeHeader.clean_url`, rescuing `ApiError` to drop bad links.
- [ ] **Step 4: Run** the spec, then `./run rspec`. Expected: PASS.
- [ ] **Step 5: Commit.** `git commit -m "Add CV import record and draft normaliser"`

### Task 2: Extractor (the only Claude call)

**Files:**
- Create: `backend/app/services/cv_imports/extractor.rb`, `backend/app/services/cv_imports/docx_text.rb`
- Modify: `backend/Gemfile` (`anthropic` is already added on this branch; add `rubyzip`), `docker-compose.yml` (backend `ANTHROPIC_API_KEY: ${ANTHROPIC_API_KEY:-}`)
- Test: `backend/spec/services/cv_imports/extractor_spec.rb`, `backend/spec/services/cv_imports/docx_text_spec.rb`

**Interfaces:**
- Produces:
  - `CvImports::Extractor.configured? -> Boolean` (the API key is present);
  - `CvImports::Extractor.new(client: Anthropic::Client.new).call(data: String (raw bytes), media_type: String) -> Hash`, which returns the parsed model JSON;
  - `CvImports::ExtractionError < StandardError`, whose message is shown to the user as is;
  - `CvImports::DocxText.call(bytes) -> String`.

- [ ] **Step 1: Write failing specs.** Use a fake client object whose `beta.messages.create(**params)` records the params and returns a canned message (`Struct`s with `stop_reason` and `content` holding `type` / `text`):
  - **PDF request shape:** a document block with `media_type: "application/pdf"` and the Base64 of the bytes; `fallbacks: :default`; the betas include `"server-side-fallback-2026-07-01"`; `output_config[:effort] == :low`; `output_config[:format_][:type] == :json_schema`; the schema has `additionalProperties: false` at every object level.
  - **DOCX request shape:** a text block containing the extracted text, and no document block.
  - **Success:** returns the parsed JSON from the text block, skipping thinking blocks.
  - **Failures, each raising `ExtractionError` with its message:**
    - `stop_reason: :refusal` → "We couldn't read this CV."
    - `:max_tokens` → "This CV is too long to read in one go."
    - invalid JSON → "We couldn't read this CV."
    - `Anthropic::Errors::RateLimitError` / `InternalServerError` / `APIConnectionError` → "The CV reader is busy. Try again in a minute."
  - **DocxText:** a `.docx` built in the spec with `Zip::OutputStream` (holding `word/document.xml` with two `<w:p>` paragraphs) returns their text on two lines. Non-zip bytes raise `ExtractionError` ("This Word file couldn't be opened.").
- [ ] **Step 2: Run** both specs. Expected: FAIL (uninitialized constant).
- [ ] **Step 3: Implement.**
  - **Schema** as in Task 1: every property required, strings for unknown values (empty string), `kind` as an enum.
  - **System prompt:**
    - copy text faithfully and never invent anything;
    - one section per job, degree or project;
    - put skills, summary and similar in their own sections;
    - for jobs and education, set `title` to the organisation name;
    - dates as `YYYY-MM`, or empty if unknown;
    - mark the role as current when it says "present" or "now".
  - **Error rescues:** the specific SDK errors (most specific first), then `Anthropic::Errors::APIStatusError` → "We couldn't read this CV. Try again later."
- [ ] **Step 4: Run** both specs and the full suite. Expected: PASS.
- [ ] **Step 5: Commit.** `git commit -m "Add Claude-based CV extractor"`

### Task 3: Job, endpoints and applying a draft

**Files:**
- Create: `backend/app/jobs/cv_import_job.rb`, `backend/app/controllers/cv_imports_controller.rb`, `backend/app/blueprints/cv_import_blueprint.rb`
- Modify: `backend/config/routes.rb`, `backend/app/models/cv_import.rb` (`apply!`)
- Test: `backend/spec/jobs/cv_import_job_spec.rb`, `backend/spec/requests/cv_imports_spec.rb`

**Interfaces:**
- Consumes: `Draft.from_model_output`, `Extractor#call`, `ExtractionError`, `Extractor.configured?`.
- Produces:
  - **Routes:** `POST /api/v1/cv_imports` (multipart `file`), `GET /api/v1/cv_imports/:id`, `POST /api/v1/cv_imports/:id/apply` with `{ section_indexes: [Integer], fill_profile: Boolean }`.
  - **Blueprint fields:** `id, status, filename, error_message, result, applied_at, created_at`. `source_data` is never serialised.
  - **Model:** `CvImport#apply!(section_indexes:, fill_profile:) -> { "section_templates" => [...], "profile" => Hash }`.

- [ ] **Step 1: Write failing specs.**
  - **Job:**
    - success stores the draft, sets `succeeded` and clears `source_data`;
    - an `ExtractionError` sets `failed` with its message and clears `source_data`;
    - an unexpected error sets `failed` with a generic message, then re-raises;
    - a draft with no sections and an empty header fails with "We couldn't find any sections in this file."
  - **Create:**
    - a PDF returns 201/200 with `status: "pending"` and enqueues the job (`have_enqueued_job`);
    - a `.txt` file returns 400;
    - a file over 5 MB returns 400;
    - an 11th import within 24h returns 429;
    - with no key configured it returns 503;
    - unauthenticated returns 401.
  - **Show:** another user's import returns 403. The response never includes `source_data`.
  - **Apply:**
    - creates templates only for the chosen indexes, in order;
    - `fill_profile` fills only blank profile fields and adds new links without duplicates;
    - applying twice returns 422;
    - applying an import that isn't `succeeded` returns 422;
    - out-of-range indexes are ignored.
- [ ] **Step 2: Run** them. Expected: FAIL.
- [ ] **Step 3: Implement.**
  - The job calls `Extractor.new.call` with `Base64.decode64(source_data)`.
  - The controller reads the upload, checks the type with `Marcel::MimeType.for(io, name: filename)`, stores Base64, and calls `CvImportJob.perform_later`.
  - `apply!` runs in a transaction, uses `user.section_templates.create!`, and fills the profile through `user.update_resume_profile!`.
- [ ] **Step 4: Run** `./run rspec` and `./run lint`. Expected: PASS.
- [ ] **Step 5: Commit.** `git commit -m "Add CV import endpoints and background job"`
